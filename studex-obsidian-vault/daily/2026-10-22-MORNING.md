| Fix | Detail |
|---|---|
| **Warmup engine endpoint** | Was POSTing to `/inboxes/{x}/messages` and `/messages`; AgentMail v0 needs `/inboxes/{x}/messages/send`. **Both 404'd since 3 Oct — 19 days of zero sends**, while logging `Sent 2 emails` regardless. Now counts real success/failure. |
| **Warmup copy de-banned** | Removed `booth confirmed`, `Hall B, African Nations Pavilion`, `PROWTC` (a *buyer*, not our certification), retired caviar name `Sevruga`, `500g per tin`, `R380/tin`, `14-21 days` lead time, and off-registry biltong/coffee prices — all sent out of real Studex inboxes. |
| **Warmup HTML escaping** | `daily-warmup-runner.js` interpolated body text into HTML unescaped → added `escapeHtml()`. |
| **Seed sends removed** | Was sending to `noreply@google.com` and `mailer-daemon@amazon.com` — a mailer-daemon generates a **hard DSN**, the exact signal a warmup must not create. |
| **Build Hour cron** | **323/323 runs had errored.** 246 × timeout (`timeoutSeconds` was 120, script sleeps between sends) + 77 × missing delivery channel. Its payload pointed at **`#build-log`, a channel that does not exist**. Now `--timeout-seconds 3600 --no-deliver`. **First green run in 324.** |
| **Daily warmup cron** | 30/30 runs errored on the same missing-channel error — script ran fine, *job* failed on delivery, so the scheduler reported an error on a successful run. |
| **Fleet-wide cron fix** | Two channels are configured (telegram, discord), so any `delivery.mode: announce` job without an explicit `delivery.channel` cannot resolve a target. **Every such job errored 100% of the time while doing its work perfectly.** Affected: Morning Nudge 54 · Content Agent 70 · Vault Sync 14+2 · Warmup 30 + 323 · Evening Standup 2 · Daily Post 1. |
| **Evening Standup cron** | Fired ~8h early (06:54 UTC vs 15:00 UTC) and had timed out at 300s → `--timeout-seconds 900 --best-effort-deliver`. |
| **Content agent** | Provider chain repaired, catalog re-synced to the registry, `validateCaption()` guard added, `max_tokens` 6000, `temperature` 1, Kimi promoted to primary. |

**Two lessons worth carrying forward:**
- *A drift checker only covers the files it scans.* The warmup engines were a **fourth** copy of the outreach copy and nobody had added them to the alarm.
- *A job can print perfect output and still be failing 100% of the time.* The failure was in **delivery**; the scheduler records delivery failures as job failures. **Read `consecutiveErrors` and the run history, not the job list.**
