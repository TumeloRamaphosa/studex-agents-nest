## 1. Studex Price Desk — live app ⭐

**URL (public):** https://jisom3k4i126.space.mcode.io
**Source:** `/workspace/studex-price-desk/`
**Stack:** Vite 8 + React 19 + TypeScript · Node build-time price fetcher

### What it does

- **Live ICE Arabica C** (ICE Futures via Yahoo chart API, KC=F) — server-side fetch at build time,
  because Yahoo sends no CORS headers and a browser cannot read it directly.
- **Live FX** (USD/ZAR, USD/CNY) from exchangerate-api.com, **cross-checked** against the ECB reference
  (frankfurter.dev) — the two providers must agree within 0.5% or the audit fails.
- **Live refresh in the browser** — the FX rate updates in the page; if the network blocks it, the build
  snapshot stays and the page says so rather than showing a silent stale number.
- **The coffee FOB band** — our published $4.80/kg sheet price against the live ICE C benchmark, with
  the recommended quote band and the Best of Rwanda 2026 record framed as a **ceiling proof**.
- **The SA Coffee Price Index** (Q3 2026) as the local-market reference.
- **Our published caviar retail prices** — and nothing else.

### 🔒 The most important thing in this build: what is NOT on it

`studex-meat/CAVIAR-TRADE-DESK-EXPOSURE-FINDING-2026-10-24.md` records that the caviar trade desk is
published on a **public URL and hands every visitor our farm-gate cost, duty assumptions, landed cost,
minimum viable price and wholesale trade price.** That finding is still open, awaiting a decision.

**I did not rebuild that mistake.** The cost model was moved into `src/costModel.ts`, which the public
entry point never imports, and it builds to a **separate output directory** (`dist-internal/`) so it
cannot be published by accident as part of a public deploy.

**And there is now a gate that makes the mistake impossible to repeat:**

```
npm run build   →  ... vite build && node scripts/audit-bundle.mjs
```

`scripts/audit-bundle.mjs` greps the public bundle for **29 internal identifiers and the old internal
numbers** (`farmGateUsdPerKg`, `dutyRate`, `landedZarPerKg`, `floorZarPerKg`, `18.5`, `23042`, `32917`,
`34000`, …) and **fails the build** if any is present. It also asserts the *internal* bundle still
carries the cost model — so a refactor cannot silently strip the internal tool either.

```

[audit] PASS — internal build carries the cost model (5 markers confirmed)
```

## 4. The caviar "pricing defect" was partly our own stale FX

The 23 Oct finding — all three SKUs quoted below cost — **does not survive a correct model**:

| SKU | Landed @ live FX | Landed @ 18.5 | Floor @30% | Trade | Margin | Verdict |
|---|---|---|---|---|---|---|
| Oscietra Imperial | R20,674 | R23,042 | R29,535 | R34,000 | **39.2%** | ✅ clears floor |
| Kaluga Prestige | R14,706 | R16,382 | R21,009 | R22,000 | **33.2%** | ✅ clears floor |
| Sevtruga Medium | R8,738 | R9,722 | R12,483 | R12,500 | **30.1%** | ✅ clears floor (R17 headroom) |

Oscietra — the SKU the old model said was R3,661 short — has **R4,465 of headroom**. That was a
**modelling error** (stale FX + recoverable import VAT treated as cost), not a pricing error.

⚠️ Two caveats I did not paper over: **Sevtruga clears by R17/kg** — that is noise, not margin; and if
import VAT is **not** recoverable, **Kaluga and Sevtruga both fall below floor.** Only the broker can
settle that, alongside the HS classification (1604.31 vs 1604.14.10) that decides the duty rate.

**Per the brief, caviar was not repriced.** The line did not need it.
