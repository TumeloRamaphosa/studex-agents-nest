## Topic 1: Voicebox — REASSESSED: It's a Server API, Not Just a Desktop App

### Key Findings

**Voicebox is not just a desktop app anymore.**
- GitHub: `jamiepine/voicebox` — full README reviewed tonight
- Ships a **REST API on port 17493** — can run headless on a server
- Endpoints confirmed:
  - `POST /generate` — TTS generation with language + profile
  - `POST /speak` — agent voice output (scriptable)
  - `POST /transcribe` — Whisper-based audio transcription
  - `GET /profiles` — list voice profiles
- 7 TTS engines: **Qwen3-TTS, Qwen CustomVoice, LuxTTS, Chatterbox Multilingual, Chatterbox Turbo, HumeAI TADA, Kokoro**
- 23 languages. MIT license — free for commercial use.
- MCP server built-in — can connect to Claude Code, Cursor, OpenClaw

**What changed from prior assessment:**
Previous research (Aug 27) said "desktop app only, cannot be called from OpenClaw." That's outdated. The API server mode is the key — it runs headless on Orgo VM, callable via curl from any automation.

**The catch:** Voicebox API runs locally on the machine where the desktop app is running, or via its built-in server. For Orgo VM deployment, we'd need to:
1. Install Voicebox on Orgo VM (no GUI, server mode)
2. Expose port 17493
3. Route incoming WhatsApp voice notes → Voicebox TTS → reply

This is a **realistic build**, not a weekend experiment. API mode confirmed.

**What we'd get:**
- Clone Naledi's voice from 30s of audio → brand voice model
- WhatsApp voice note received → transcribed → AI-generated reply → Voicebox TTS in Naledi's voice → sent back
- Fully automated WhatsApp CS at scale, in a real human voice
- Zero per-character TTS cost (self-hosted)
