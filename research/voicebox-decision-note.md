## 1. What Voicebox actually is

[Voicebox](https://github.com/jamiepine/voicebox) is an **MIT-licensed, local-first AI voice studio**.

| Capability | Detail | Fit for Studex |
|---|---|---|
| Voice cloning | from **3 seconds** of audio | 🔴 **This is the headline.** 3s of Tumelo becomes the coffee/biltong WhatsApp voice. Never leaves our infrastructure. |
| TTS engines | **7**: Qwen3-TTS 1.7B/0.6B, Chatterbox, Chatterbox Turbo, LuxTTS, Qwen CustomVoice, TADA, Kokoro 82M | 🔴 **Kokoro (82M, CPU) and LuxTTS (~1GB VRAM, 150× realtime on CPU) run on our 2-CPU / 8GB Orgo VM with NO GPU.** |
| Dictation | Whisper, **99 languages** | 🟡 Useful for internal notes; not a customer-service need. |
| MCP server | `http://127.0.0.1:17493/mcp`, tool `voicebox.speak` | 🟡 We already run an MCP client (matrix-mcp) — wiring is cheap once it exists. |
| REST | `POST /speak` | 🟢 **Use this.** Simpler than MCP for a WhatsApp reply pipeline. |
| Personality layer | rewrites copy in character | 🟡 Nice for the Naledi/brand voice. |

**Licence:** MIT — no lock-in, no per-minute vendor, no data leaving the box.

## 2. The economics

| Option | Marginal cost | Notes |
|---|---|---|
| **Voicebox (self-hosted)** | **$0** | CPU-only, runs on the Orgo VM we already pay for. |
| ElevenLabs | per-minute | We already hold a key (`ELEVENLABS_API_KEY`), but it is a recurring bill that scales with every WhatsApp reply. |

At our volume the absolute saving is small. **The real argument is not cost — it is control:** a cloned
brand voice that never leaves our infrastructure, and a voice tier that cannot be switched off by a
vendor changing their pricing or their API.

## 3. 🔴 What Voicebox does NOT do — the constraint that decides this

**Voicebox is a speech-OUT engine. It does not answer the phone.**

Running customer service on it requires five things, and **Voicebox is only one of them**:

| # | Requirement | Voicebox provides? |
|---|---|---|
| (i) | **Inbound voice capture** — WhatsApp Business API voice notes, or a telephony leg | ❌ **NO** |
| (ii) | **ASR on the inbound side** — turn the customer's audio into text | ⚠️ Whisper dictation exists but is a desktop dictation feature, not a telephony STT pipeline |
| (iii) | **The agent brain** — our orchestration, tools, memory | ❌ no |
| (iv) | **Policy / script layer** — what the agent may and may not say to a customer | ❌ no |
| (v) | **Human handoff** — escalate to a human on a real signal | ❌ no |

**That is a multi-day build, not a Build Hour build.** Starting it tonight would produce a talking
demo with no customer attached — the exact failure mode this workspace keeps paying for.

## 4. Why not tonight — the sequencing argument

Three deadlines are closer than the value of the voice tier:

1. **Kigali Summit — 4 days away.** A brand-voice WhatsApp line is worth most exactly when we are
   chasing CIIE/Kigali leads. But those leads do not exist yet in volume, and a broken reply line on a
   live number is worse than no reply line.
2. **CIIE — 12 days away.** Same logic, larger prize, same constraint.
3. **The price band work is unfinished.** A voice that quotes the wrong price is a liability. We only
   just fixed the price basis (`research/2026-10-24-price-reality-check.md`); the Kigali partner has
   not yet confirmed the $4.80/kg figure. **Do not let a voice bot speak prices we have not settled.**

**Decision: build the decision note now, the install after Kigali.** This note exists so the question
is not re-researched next week.

## 5. The half-day feasibility plan (when the window opens)

Ordered so that each step is independently useful and can be abandoned.

| Step | Work | Time | Output / gate |
|---|---|---|---|
| 1 | Install Voicebox on the Orgo VM (Linux binary or source build) | 30 min | `voicebox` runs; **abort if it wants a GPU** — Kokoro/LuxTTS must run CPU-only |
| 2 | Bring up **Kokoro 82M** first (smallest model) and confirm CPU inference | 30 min | one WAV out of a text line |
| 3 | `POST /speak` — turn the WhatsApp reply text into a WAV | 30 min | a scripted reply renders to audio |
| 4 | Clone the brand voice from a **3-second Tumelo clip**; compare against the plain Kokoro voice | 45 min | **the gate: if the clone is not clearly better, stop here and use ElevenLabs** |
| 5 | Wire to a **test WhatsApp number** (not the customer-facing one) | 45 min | a reply arrives as a voice note |
| 6 | Add the **policy layer** — the reply text is generated by our existing agent brain and its tool output, never free-form | 1 h | no unbounded generation reaches a customer |
| 7 | **Human handoff rule** — any order, complaint, refund or complaint-adjacent message goes to a human | 30 min | documented escalation trigger |
| 8 | Inbound: WhatsApp voice note → ASR → agent → TTS reply | 1–2 days | **this is the multi-day part — only after steps 1–7 are proven** |

**Total for steps 1–7: roughly one day, not half a day.** Steps 1–5 fit a half-day; steps 6–7 are
where the risk and the effort both live. **Do not let the "half-day" framing skip steps 6–7** — a
voice bot with no policy layer and no handoff is a liability on a customer-facing number.

## 6. Prerequisites and blockers

| Item | State |
|---|---|
| Orgo VM | 2 CPU / 8GB RAM — **sufficient for Kokoro and LuxTTS on CPU.** No GPU needed for the recommended path. |
| Orgo API access | ⛔ **The Orgo API keys in `.env` currently return HTTP 401.** The VM is reachable by SSH (`67.213.119.157`), so the install can still proceed — but the *automation* path needs a working key. |
| Brand voice clip | ⛔ **Not recorded.** Needs 3 seconds of clean Tumelo audio. Must be consented and stored deliberately. |
| Test WhatsApp number | ⛔ **Not provisioned.** Do not test on the customer-facing number. |
| Agent brain + policy layer | 🟡 Existing orchestrator exists; the *policy* layer for customer voice is new work (step 6). |
| ElevenLabs fallback | 🟢 Key already held — this is the fallback if the clone underperforms. |

## 7. Recommendation

1. **Do not install Voicebox before Kigali.** The sequencing cost is higher than the benefit.
2. **After Kigali**, run steps 1–5 as a single half-day spike with one explicit gate at step 4: *is the
   cloned voice good enough to beat ElevenLabs?* If no, we keep ElevenLabs and we have lost one day.
3. **Never let steps 6 and 7 be skipped** to "get it live faster". A voice agent that can quote,
   promise and argue on a customer-facing number without a policy layer and a human handoff is a
   liability we cannot afford.
4. **Keep the MCP route in reserve.** `POST /speak` is the right integration for a WhatsApp pipeline;
   the MCP server is the right integration if the voice agent ever joins our agent fleet.
