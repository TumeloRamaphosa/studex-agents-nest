## TOPIC 1 — Voicebox: what it is, and could it power Studex customer service?

### Key findings

- **What it is:** MIT-licensed, **local-first open-source AI voice studio** — ~58.4k GitHub stars. It is a combined **ElevenLabs + WisprFlow + voice-cloning** replacement: 8 local TTS engines (Qwen3-TTS, Qwen CustomVoice, Qwen VoiceDesign, LuxTTS, Chatterbox Multilingual, Chatterbox Turbo, HumeAI TADA, Kokoro), **Whisper** STT, and a **bundled Qwen3 LLM** for transcript cleanup and persona rewriting. **Free forever, no API keys, no per-character cost.** ✅ *(repo cloned to `/workspace/vendor/voicebox` and read)*
- **It exposes an MCP server — which is the whole point for us.** ✅ Four tools: `voicebox_speak`, `voicebox_transcribe`, `voicebox_list_captures`, `voicebox_list_profiles`. Endpoint is **Streamable HTTP at `http://127.0.0.1:17493/mcp`**, mounted inside the same uvicorn process as the FastAPI app, with an `X-Voicebox-Client-Id` header that binds a distinct voice profile per agent. That means **each OpenClaw agent gets its own cloned voice** — Robusca, Naledi, Biltong, the coffee agent, each speaking differently.
- **Our 18 Oct setup plan was wrong in four places.** ✅ The old plan said port 3010, `node cli.js clone`, `npm install`, and `packages/mcp-server/dist/index.js`. **None of those exist.** The real API port is **17493** (Docker maps host **17600 → 17493**); there is **no CLI clone command** (cloning is via the app UI or the profiles API); the backend is **Python** (`just setup` / `just dev`, needs Python 3.12 + Bun + Rust + `just`), and the MCP server is **HTTP, not a separate stdio node process**. Had we followed the old plan on the Orgo VM, it would have failed on step 1. Corrected runbook written to `studex-voice/VOICEBOX-DEPLOY.md`.
- **Hardware decides everything.** ✅ Repo asks for **4 CPU / 8GB RAM**; Lightweight options exist (**LuxTTS ~1GB VRAM / 150× realtime**, **Kokoro 82M CPU realtime**). Our MaxClaw box is **1 CPU, 4GB RAM, no GPU, 5.5GB disk free** → **not viable**. The **Orgo VM (2 CPU, 8GB RAM) is the right host** — it matches the RAM ask, and on its 2 CPUs we must use **LuxTTS or Kokoro, not Qwen3-TTS/Chatterbox**. The **Alibaba ECS (2 vCPU / 2GB) is too small**, and its SSH port 22 also **timed out** tonight. ✅
- **The ElevenLabs "fast path" fallback in the old plan is dead.** ✅ Our key `sk_93f…` returns **401 `missing_permissions`** for both `voices_read` and `text_to_speech`. ElevenLabs is **not** currently available as a fallback. What *does* work tonight is the platform's own MiniMax TTS — used below to produce three real voice notes. ✅

### Opportunities for Studex

1. **A differentiated service no SA competitor has.** Luxury meat is a spoken-sale category: "my ribeye is one thousand nine hundred and fifty rand, how would you like it cooked?" A **voice-ordering agent** on WhatsApp is a genuine differentiator against Checkers, Meat World, Woolworths — all of whom are silent e-commerce. Nobody in SA luxury meat is doing voice.
2. **Zero marginal TTS cost at scale.** Every order confirmation, delivery update, and FAQ reply is free after the one-off model download. Currently every WhatsApp reply is a human minute — at our volume that is the single largest avoidable cost in the order funnel.
3. **Per-agent brand voices.** The `X-Voicebox-Client-Id` binding means Naledi can sound like the CMO, the Biltong agent like a butcher. One server, many voices, no extra hosting.
4. **Voice notes beat text for gifting.** Caviar and biltong are emotional purchases. A WhatsApp **voice note** ("Tumelo here — I've added the Caviar and a bottle of our oldest Shiraz") converts better than a text receipt and is a *differentiation* device, not a feature.
5. **Privacy is a selling point for corporate gifting.** Local inference = no customer voice data leaves the machine. We can say that to hotel and corporate buyers who are currently nervous about voice AI.

## TOPIC 2 — Agent automation: what actually shipped this week, and what Studex should do

### Key findings

- **n8n shipped three releases in October (2.43 on 6 Oct, 2.44 on 13 Oct, 2.45 on 20 Oct) and three features change our stack.** ✅ **Browser Use is now GA** (2.43) — n8n agents can drive a real browser natively; we no longer need a separate scraper/browser node. **Durable scheduler is on by default** (2.45) and **legacy Cron nodes now run on it** — our `Schedule Trigger` in `studex-content-pipeline.json` should be migrated. **Idempotency-Key support on Public API POSTs** (2.45) — this is the fix for duplicate Shopify-order processing, the classic failure mode of our order pipeline. **Agent budget guardrails** (2.43 → 2.45) with live budget panels and execution stops — this finally makes agent spend predictable.
- **Make AI Agents now run on a fallback connection with prompt caching, and support GPT-6.1 Sol + Claude Sonnet 5.5** (Make's Oct 19 product update) ✅ — the fallback connection means an agent keeps running when the primary model is down, which is exactly what a customer-facing agent needs. Make's **Oct 16 release retired Twilio Autopilot** — a migration warning, not a blocker.
- **Higgsfield shipped the most interesting thing for us this month.** ✅ **Content Factory** (22 Oct) turns a "what if" prompt into finished 15s–5min clips including script, characters, voiceover and editing — a **product-to-video pipeline in one call**, and it is the natural AI-influencer layer for our biltong/coffee content. **Ad Multiplier** (6 Oct) takes one winning video ad and recreates it with *our* products, cast and locations — that is a **performance-ad cloning machine**, and our content pipeline already has a Higgsfield node. **Kling 4.0** landed 21 Oct with up to 15 references, 3–30s at 1080p. **Katana** (8 Oct) is a **Claude skill via MCP** that creates video edits from a single reference photo. Credits are cheap at the low end (Ad Multiplier ~140 credits ≈ $7 for 720p) and **API rates are 60% off Wan 3.0 until 31 Oct 2026** ✅ — a deadline worth using.
- **Our own stack has a real defect that nobody has flagged.** ✅ `n8n-workflows/whatsapp-shopify-autoreply.json` **was invalid JSON** — two unescaped `\'` sequences inside a `jsCode` string — so it could not have been imported into n8n at all. **Fixed and re-validated tonight.** The workflow (WhatsApp webhook → order-number parse → Shopify lookup → status reply → Discord log) is now importable for the first time.
- **Blotato is connected but under-used.** ✅ 7 accounts live (Facebook personal, YouTube "Studex Wildlife", 2× Instagram, LinkedIn, Threads, TikTok). The **"Studex Meat" Facebook Page and `studex.meat` Instagram are still NOT connected** — the Meta page token expired 27 Jun 2026. We are posting to personal and lifestyle accounts, not to the brand accounts where the buyers are.
- **The credential queue is unchanged and still the binding constraint.** Shopify Admin token, Meta Page token, GitHub PAT (33+ commits unpushed), FeedHive key, Orgo key, ElevenLabs scope. **Every one is an owner action; no tool substitutes for a missing credential.**

### Opportunities for Studex

1. **Higgsfield Content Factory + Ad Multiplier is the fastest revenue-shaped automation available to us.** Ad Multiplier is literally "take our best-performing ad and swap in our product" — our content pipeline already has a Higgsfield node and a Blotato publish node. The wiring exists; the *credible creative input* doesn't. Build one strong Wagyu biltong hero video, then let Ad Multiplier generate 10 variants for Meta.
2. **n8n's Idempotency-Key closes our duplicate-order risk.** A double-processed Shopify order means a double courier, a double courier cost, and an angry customer. One flag on the Public API POST.
3. **Browser Use in n8n is a cheap competitor-intelligence engine.** It can open our competitors' product pages and pull prices/stock positions on a schedule — the pricing benchmark our briefs keep doing by hand.
4. **Content Factory replaces our "script → voiceover → edit" content pipeline with one call.** That frees Naledi to write and approve rather than assemble.
5. **Make AI Agents with fallback connections is a better host for the *customer-facing* agent than n8n** (fallback = never goes dark mid-order). But we only adopt it if we adopt it as the primary path — two orchestrators is worse than one.
