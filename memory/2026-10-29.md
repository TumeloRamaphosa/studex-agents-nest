### 🔴 But `warmup.log` was silently destroying the runner's own audit trail
The same defect was flagged on **2026-10-28** ("warmup.log is silently losing
the daily runner's entries") — **and never actually fixed.** Root cause, now
confirmed exactly:

Two writers, opposite orders.
* `index.js` `log()` — **prepends** the new line and keeps the **newest 500**
  (`[line, ...existing].slice(0, 500)`).
* `daily-warmup-runner.js` `appendLog()` — **appends** to the end.

The runner's `[SENT]` lines therefore live at the **tail**, and every `index.js`
cycle slices them off the head. Proven by simulation on the real file:
**after one `index.js` cycle → 0 of 30 `[SENT]` lines survived**, and the file
tail reverted to **2026-10-12**. The audit trail only existed because the daily
cron happened to run *after* the build-hour cycle that day.

Second, smaller defect: `index.js` wrote **without a trailing newline**, so the
two writers **glued** lines together — one line in the file carried two
timestamps, corrupting a 2026-10-12 error record.

**Fixed** (`studex-email-warmup/index.js`, 8 insertions / 2 deletions):
append chronologically and trim the **oldest** instead of the newest, and
terminate with a newline. The one legacy glued line was split (533 lines, all
parse cleanly, all 30 `[SENT]` preserved).

**Verified in an isolated copy** (`/tmp`, real state untouched, `--dry-run`
only, no sends): after a full `index.js` cycle → **30/30 `[SENT]` survive**, 0
glued lines, oldest line now 2026-10-27 instead of 2026-10-12, newest at the
tail. `node --check` clean on both files.

🔑 *A log that is written by two writers must agree on direction. When one
prepends and one appends, the cap silently eats whichever one is at the tail —
and the file looks fine right up until the audit trail you needed is gone.*
