shape character class is `[A-Za-z0-9._-]`, which excludes newline and carriage
return, so a shape match can never span a line boundary. The greedy run is confined
to its line whether you scan the file whole or line by line. Memory is now constant
regardless of file size.
- `CHUNK = 4 MiB`, `MAX_LINE = 32 MiB` (segmented with a 4096-byte seam overlap),
  `SHAPES_BYTES` (bytes regexes — no decode, so no 2x blow-up).
- The buffer is index-scanned with `buf.find(b"\n", pos)`, NOT `buf.split(b"\n")`:
  `split()` materialises every line of the chunk at once (~550k bytes objects for a
  4 MB chunk) — a second memory spike on top of the buffer.
- `tracked_literals()` got the same treatment (it also slurped whole files).

**Measured:** peak RSS **69 MB** on the real 2.9 GB /tmp (was OOM-killed);
**32 MB for a 96 MB file, and byte-identical for a 1 MB file — growth 0 MB**.
Coverage *increased*: `orphan DEAD` went 24 -> 25, because the 485 MB pack is now
actually read for the first time.

**New test `ops/test-tmp-shape-memory.py`** (registered in `ops/run-tests.sh`):
runs the REAL audit against a 96 MB file with a synthetic literal at EOF, measures
peak RSS per run in a fresh process, and asserts (1) it completes, (2) it still
FINDS the literal — a streaming bug must not become a "finds nothing, so clean"
false negative, and (3) peak RSS does not grow with file size. The test found the
real bug the checker could not.

### Defect 2 — the runner would have reported a REAL credential exposure as "the checker crashed"
`ops/tmp-shape-surface-audit.py` exits **3 for EXPOSED** (its own convention), and
`ops/run-heartbeat-checks.py` hardcoded `rc == 3 -> BROKEN`. So a genuine live-credential
exposure under /tmp would have been reported as "the checker died" and **thrown away** —
the pass would say BROKEN instead of EXPOSED, and the correct response (redact the
credential) would have been replaced by the wrong one (fix the crash). The registry
also listed the contract as `0,1,-`, which was simply wrong for this checker.

**Fix — classification is now CONTRACT-DRIVEN.** Each checker declares
`(clean, finding, could-not-prove)` in `ops/heartbeat-checkers.tsv`; the runner reads
that contract instead of hardcoding 0/1/2/3. An exit code a checker never declared is
treated as a FINDING, never as clean. Missing/crashed/timeout now use explicit flags
instead of a magic rc=3, and a signal kill (negative rc) is BROKEN, not a finding.
Registry corrected to `tmp-surface | 0,3,-`. The runner now also PRINTS a warning when
a checker returns an undeclared code, so contract drift surfaces instead of being
silently binned.

**Verified across ALL 14 PASS checkers:** every declared contract matches the real
exit code — **0 mismatches**. `tmp-surface` was the only one with a non-standard
finding code.

**The contract test was drifting:** `ops/test-runner-contract.py` carried a LOCAL COPY
of the classification logic — which is exactly how a test passes while the shipped
runner does something else. It now imports the runner's real `classify()` and asserts
the regression directly (a checker declaring 3 as its finding code must classify as
FINDING, never BROKEN, never CLEAN; an undeclared code must never be CLEAN).
