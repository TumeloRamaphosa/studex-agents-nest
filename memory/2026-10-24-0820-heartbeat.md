# 2026-10-24 08:20 UTC — Heartbeat: the /tmp audit was MANUFACTURING its own finding

## The finding
The 08:20 scan reported **EXPOSED — 4 Orgo literals** in the active gateway log
(`/tmp/openclaw/openclaw-2026-10-23.log`). Chasing it produced the opposite of a leak.

## Root cause — a self-amplifying loop
The Orgo key has **no distinctive prefix** (`sk_live_` is a generic Stripe-shaped string),
so it fell through to `unknown (no probe for this prefix)`. UNKNOWN counts as exposure by
design, so:
1. the audit flagged a **DEAD** key as exposure
2. the redactor masked it in the gateway log
3. the next diagnostic **printed the key** → the gateway logs tool output → the key
   **reappeared** → the masked count climbed **4 → 17 in 90 seconds**

🔑 **The audit was generating the exposure it reported, and a diagnostic that merely LOOKED
at the key re-published it into /tmp.** Reading a secret with a tool that logs its output is
itself an act of publication.

🔑 **A "no probe" verdict is not a neutral state.** UNKNOWN → exposure → mask → regenerate is
a loop, not a fix. A credential family with no probe must be given a probe, or the tool
will churn on it forever.

## The key is DEAD
Probed directly: `GET https://www.orgo.ai/api/computers/946b3156-...` → **HTTP 401**.
`GET /api/computers` (collection) → **405**, a *method* error that says nothing about the
key — the collection URL is deliberately not used.
