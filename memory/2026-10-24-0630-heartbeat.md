## Two false greens found and fixed — commit `42db914c`

Same shape in both: **a checker that looked where it expected to find the
problem, and so missed it.**

### 1. `ops/tmp-credential-surface-audit.py` probed AgentMail in the wrong dialect
The probe sent a bare `Authorization: am_us_...` header. AgentMail answers
**403** to that and **200** to `Authorization: Bearer <key>`. So every live
AgentMail key was classified **DEAD** — and DEAD is precisely the class the
redactor leaves untouched. **A live key was being read as proof of death.**

Both probes now carry the scheme the API actually requires.

### 2. A doc-pointer emitter was not a credential reference
`ops/repair-doc-credential-pointers.py` (added by a concurrent session in
`4ceec1e1` at 06:51) is a **DOC-POINTER EMITTER**: it writes the text
`${VAR}` into markdown so a human can look the value up in `.env`. Python
not expanding it is the design. The resolution rule fired on it → **red suite**.

The fix is narrow and self-declared on purpose:
- `ALLOW` skips a file **entirely**, including the HARDCODED-literal scan.
  Allowing this file wholesale would have let it carry a live key undetected
  — the exact blind spot the checker exists to close.
- Instead the file declares `# credential-resolution: doc-pointer-emitter`,
  which exempts the **`${VAR}` resolution rule only**. The HARDCODED scan
  still runs over the file in full.

Two regression cases prove both halves:
- marked emitter containing `${VAR}` → **GREEN**
- marked emitter containing a **live key** → still **RED**

## Lesson (reinforced, twice over)
Both bugs were the same mistake the repo already documents: *a rule that only
covers what it scans is decoration.* A probe that speaks the wrong dialect is
a probe that reports the wrong world — and it reported "DEAD" for things that
were alive, which is the most dangerous possible direction for it to fail in.
