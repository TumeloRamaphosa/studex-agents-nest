## 🔴 But the push blocker needed measuring, and it was not what we had recorded

Every memory note said **"push blocked by the dead GitHub PAT"**. That phrasing
implies a single cause with a single fix: *rotate the PAT*. I measured it, and
it is **two independent problems**.

### Problem 1 — there is no credential on this box at all
| Where | Result |
|---|---|
| `/root/.git-credentials` | **0 bytes** |
| `git credential fill` (github.com) | **nothing** — *could not read Username* |
| PAT in `TOOLS.md` / `.env` | **none** |
| `gh` CLI | not installed |
| `~/.ssh` | `known_hosts` only — **no key**; `ssh -T git@github.com` → *Permission denied (publickey)* |
| the **published** PAT (`github_pat_…`, 93 chars) | **HTTP 401 "Bad credentials"** → **REVOKED** |

So "dead PAT" was right in the narrow sense and wrong in the way that matters:
there is nothing here to rotate *into*. A new credential has to be created.

### Problem 2 — a push would need `--force`
`HEAD` and `origin/master` have **no merge-base**. Our history was rewritten in
place, so the local lineage and the published lineage are unrelated.

🔑 **The trap here is worth naming.** *"106 commits behind"* reads like a
collaborator pushed work we would clobber. **It isn't.** Those 106 are our own
**discarded pre-rewrite history** (Jul 2–20) — `origin/master`'s tip
`cd59bac7` (2026-07-20) is **not an ancestor of our HEAD**. And `origin/master`
has not moved since 2026-07-20: nobody has pushed in three months.

**So the force-push is safe — there is no third-party history to destroy.**

## What I did NOT do, and why

**No push.** There is no credential, and force-pushing published history is
outward-facing and hard to reverse. It needs the owner's explicit go, not my
judgement.

## Owner actions, in this order

1. **Rotate Blotato + GoDaddy FIRST.** Both dashboard-only. A rewrite without a
   rotation leaves a working credential someone has already cached.
2. **Create a repo-scope PAT → `/workspace/.env` as `GITHUB_TOKEN`.**
   *Not* `TOOLS.md` — that file is injected into context every session, so a key
   there is a leak path, not a store.
3. **Authorise the force-push.**

The moment the PAT lands I can run it.

## 🔑 Lesson

**A recorded blocker that names only its most obvious cause sends the owner to
fix the wrong thing.** "Dead PAT" pointed at rotation. The real answer was
*create a credential* **and** *authorise a force-push* — and the second one only
became visible by measuring the merge-base instead of reading the note.

Measured, not inferred: the difference between "rotate the PAT" and "create a
PAT, then force-push, and rotate Blotato first" is the difference between a
half-done fix and a closed exposure.
