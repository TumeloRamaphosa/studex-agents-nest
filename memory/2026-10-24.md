runtime → **caught by the surrounding `catch` blocks** → which return

🔑 **So the war-room's Blotato panel was showing FAKE connected accounts and
FAKE scheduled posts, presented as live.** Nobody saw an error, because the
catch swallowed the ReferenceError. 🔑 **This is the repo's own rule again: a
green tick that asserted nothing is worse than no checker** — except here the
green tick was a UI, and the assertion it was making was "7 accounts
connected", which was never true.

**And the proxy it was reaching for does not exist.** There is **no
`/api/blotato` route** in any server in this repo — no `studex-war-room/server/`,
no `api/`, and the only mention of the route is a *comment* in
`scripts/cred_env.cjs:35` saying the war-room VM ought to have it. The client
was pointed at a route that was never built, with a browser-side key as the
stopgap.

🔑 **That is why the key was in the browser at all**: the proxy was planned,
the route was never written, and someone put the key in the client to make
the panel light up. 🔑 **A missing server route does not stay missing — it
gets papered over in the browser.** The paper is a credential.

**The fix applied** — delete the `blotato-api-key` header from the client
entirely, exactly as the code's own comment ("NO API KEY IN THE BROWSER - the
war-room server proxies Blotato") and the repo rule ("browser bundles must
never contain API keys; route Blotato through a server-side proxy") both
demand. **Not** by defining `BLOTATO_KEY` with a literal — that would put the
live key straight back into a browser bundle.

### 🔑 A checker blind spot worth recording
`/workspace/blotato.ts` (untracked) contained the live-key **fragment**
`"${BLOTATO_API_KEY}**************************"` — the placeholder plus 21
characters of the key's tail. 🔑 **The checker's pattern is
`blt_[A-Za-z0-9]{20,}`, and the fragment does NOT match it, because the
prefix was consumed by the template placeholder.** A mangled secret defeats a
prefix-anchored scanner. Both occurrences redacted to `"${BLOTATO_API_KEY}"`.

🔑 **The general lesson: a credential scanner must match the secret, not the
secret's brand.** A key split across a placeholder, a base64 wrap, or a
concatenation is still the key. Prefix-anchored regexes are the easiest thing
in the world to write and the easiest thing in the world to fool.

- `src/components/DeliveryKPIs.tsx` → `import.meta.env.VITE_SHOPIFY_ACCESS_TOKEN`

secrets to every visitor** — a Shopify **Admin API** token (all orders incl. customer email and
address) and a ClickUp token, both also visible in the browser network tab.
