## ⚠️ COSMETIC FLAW ON THE LIVE OCT 22 POSTS — 2026-10-22
The two posts that went live at 21:16 UTC (Instagram `8384191`, Threads `8384194`) were published from the raw queue-file body, which contains markdown `**bold**` markers. **Social platforms do not render markdown** — the asterisks are visible literally in the caption. The Threads copy was a purpose-written 500-char cut, so it carries only the leading `**...**` on the headline line; the Instagram copy carries `**` on the headline too.
**Root cause:** the publish script did not strip markdown before posting.
**Fix applied:** `socialize()` added to `scripts/daily-post.py` — strips `**`, `> ` blockquote prefixes and backticks. Applied on both the Blotato and FeedHive publish paths. All future posts publish clean.
**Cannot be retro-fixed:** Blotato has no edit route (`PATCH /v2/posts/{id}` → 404) and no delete route (`DELETE /v2/posts/{id}` → 404). Only `DELETE /v2/schedules/:id` exists, which does not apply to published posts. No Instagram/Threads platform token is exposed by Blotato either (`GET /v2/users/me` returns only the Blotato API key).
**Impact:** cosmetic only — the copy, CTA, hashtags and image are all correct. **Tumelo can edit the caption directly in the Instagram and Threads apps** (both platforms allow caption editing in-app), or leave it. Do not repost to "fix" it — that would create a duplicate on a channel that has already had a year of inconsistent posting.

**Why I got it wrong:** the pending file's `status` field said `APPROVED_PENDING_FB_TOKEN` while the Blotato posts were already live. The pending file records the *Facebook* outcome; it does not reflect that the fallback platforms succeeded. Reading `status` alone is not evidence the caption is unpublished — **always query Blotato's posts API before telling anyone a post is unpublished.**

**Two separate publishers wrote to the same pending file:**
- `studex-content-automation/scripts/blotato-fallback.js` → published Threads `8383081` (and attempted LinkedIn → 422, connection expired).
- An ad-hoc `/tmp/ig2.js` script → published Instagram `8383092` with an image URL, then wrote `fallback.instagram = "POSTED"` and `status = "POSTED_VIA_FALLBACK"` back into the pending file.

**Two real defects fixed:**
1. **`blotato-fallback.js` had no idempotency guard.** Re-running it for the same date would republish the same caption to the same platforms. It now reads `pending.fallback.posted` / `pending.fallback.instagram` and **skips any platform already published for that date**, logging `SKIPPED (already published for YYYY-MM-DD)`.
2. **`socialize()` did not strip markdown that wrapped across a newline.** The regex `\*\*(.+?)\*\*` has no `re.DOTALL`, so `.` never matches `\n` — a bold span broken across lines did not match and the literal `**` survived onto the live Instagram post `8384191`. Now `re.sub(r"\*\*(.+?)\*\*", r"\1", text, flags=re.S)`. Verified: multi-line bold is stripped, single-line bold still strips correctly.

**Also fixed in `scripts/daily-post.py`:** the duplicate-prevention marker was all-or-nothing — one published platform marked the whole day done. It is now **per-platform**: `already_published(date, pillar)` returns the *set* of platforms already published, `try_blotato(..., skip=...)` skips those, and `write_marker()` unions prior and new results. Verified:
